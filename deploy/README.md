# Хостинг сайтов на Timeweb

Два домена, одна сборка. Страницу выбирает фронтенд по имени хоста
(`app/src/sites.ts`), поэтому собирать и выкатывать нужно один раз.

| Домен | Что открывается |
|---|---|
| `maple-media.ru` | сайт МЭПЛ, `/cases`, `/cases/:slug` |
| `scenika.ru` | «Сценика» с корня |

`maple-media.ru/scenika` отдаёт постоянный редирект на `scenika.ru`,
`scenika.ru/cases` — на домен МЭПЛ. Так один и тот же контент не висит
на двух адресах.

Сервер — `147.45.229.3`. Переезд с Vercel завершён 2026-09-09: A-записи
обоих доменов ведут сюда, сертификаты Let's Encrypt выпущены, автопродление
включено.

## Выкатка

```bash
./deploy/deploy.sh
```

Собирает локально, заливает релиз в `/var/www/maple/releases/<дата>`,
переключает симлинк `current`, перезагружает nginx. Хранится пять
последних релизов.

Откат без пересборки — перестановка симлинка:

```bash
ssh maple-server 'ls -1t /var/www/maple/releases'
ssh maple-server 'ln -sfn /var/www/maple/releases/<релиз> /var/www/maple/current && sudo /usr/bin/systemctl reload nginx'
```

## Доступ

Пользователь `deploy` с ключом `~/.ssh/maple_deploy`, алиас `ssh maple-server`.
Права sudo урезаны до двух команд: `nginx -t` и `systemctl reload nginx`.
Заводится скриптом `provision-user.sh` (от root, один раз).

Когда SSH не идёт — работать через веб-консоль Timeweb, она не зависит от
`sshd`. Прямой доступ ломает VPN-клиент на xray с TUN: адрес сервера нужно
держать в списке **исключённых маршрутов** приложения (не в правилах
маршрутизации, это разные механизмы), сетями целиком — `147.45.229.0/24`.

## Скрипты

| Файл | Когда нужен |
|---|---|
| `provision-user.sh` | один раз: создать `deploy`, каталоги, sudo |
| `setup-server.sh` | один раз: nginx, certbot, конфиги, http |
| `issue-certs.sh` | после того, как DNS показывает на сервер: сертификаты и https |
| `deploy.sh` | каждая выкатка |
| `diagnose.sh` | когда сервер не отвечает |
| `remove-dns-proxy.sh` | разовая чистка связки sniproxy/dnsproxy, уже отработал |

`setup-server.sh` останавливается, если порты 80 или 443 занимает не nginx.
На сервере работает телеграм-бот в Docker (`/opt/telegram-assistant`,
порт 8081) — его трогать нельзя.

## Грабли

**`http2` в nginx 1.24.** В Ubuntu 24.04 идёт nginx 1.24, где нет отдельной
директивы `http2 on;` — она появилась в 1.25. Писать флагом в строке listen:
`listen 443 ssl http2;`. Иначе `nginx -t` падает с `unknown directive "http2"`,
и перезагрузка не проходит.

**Проверка DNS перед выпуском сертификата.** `issue-certs.sh` спрашивает
публичный резолвер, а не системный: у вышестоящего DNS сервера может висеть
устаревшая запись, тогда как Let's Encrypt пойдёт к авторитетным серверам
домена и увидит актуальную.

**Проверять сайты снаружи.** Своя сеть до сервера может не добивать и давать
ложные отрицательные результаты. Надёжнее внешние узлы через `check-host.net`.

## Кэширование

`/assets/` — хешированные файлы сборки, отдаются с `immutable` на год.
`/uploads/` — картинки, 30 дней. `index.html` не кэшируется, иначе после
выкатки браузер продолжит показывать старую оболочку.
